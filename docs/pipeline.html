How a voltage trace becomes a seizure count

The pipeline turns 962 hours of continuous mouse EEG into a list of seizures with start and end times, and from that into the numbers a lab actually wants: how often the animal seizes and for how long. The data changes form five times on the way.

The end-to-end flow

Each arrow is labelled with what the data is at that point, not just that something happened. Following those labels down the page is the fastest way to understand the project: a continuous voltage trace becomes a matrix, then a probability, then a list, then a statistic.

What each stage is for

One card per stage: the goal, what goes in and comes out, and the single thing that makes that stage harder than it looks. Detail diagrams land here as we build them.

1

Acquire & audit

Establish what is actually in the files. The dataset ships with a four-line description and no documentation, so everything the loader relies on had to be measured rather than read.

in  50 .mat files, 18 GB out  verified recordings + animal keys

Training files are 1000 Hz and test files 400 Hz, which nothing documents. Missed, it corrupts every later result silently — no error, just numbers that look like a modelling failure. Four test files also claim the same animal ID, so animals are keyed by filename instead.

2

Condition & window

Put every recording on the same footing — one sampling rate, one frequency band, one amplitude scale — then cut the continuous trace into the fixed-length pieces a classifier can consume.

in  continuous trace + labels out  2.0 s windows every 0.5 s

Window length is a trade. Too short and the spectrum cannot resolve the 5.9 Hz rhythm; too long and a brief seizure is diluted by surrounding baseline. 2 seconds sits inside a typical 5.6 s event while still resolving to about 0.5 Hz.

3

Featurize & classify

Reduce each window to 21 numbers that describe its shape and rhythm, then score how seizure-like it is. The score is a probability, not a yes-or-no, because every later step needs something graded.

in  window matrix out  P(seizure) per window

Ordinary theta rhythm sits at the same frequency as the seizure. Around a quarter of normal windows peak in the same 5–7 Hz band, so frequency alone is worthless — it scores below chance. The separation comes from harmonics: a sharp spike puts energy well above its own rhythm, and a smooth oscillation cannot.

4

Form events

Turn a stream of per-window scores into discrete seizures with a start and an end. Overlapping windows are averaged into one trace per moment, thresholded with a hysteresis rule, then grouped — brief dropouts merged, fragments discarded.

in  P(seizure) per window out  (onset, offset) list

This stage decides whether a seizure is counted once, three times, or not at all. It is where the result is won: with the classifier held fixed, moving one threshold took event F1 from 0.50 to 0.80 and cut false alarms from 44.6/h to 3.5/h.

5

Evaluate & report

Match detected events against the annotator's, and turn the surviving list into seizure burden — the number a lab actually uses. Scoring is done with the community reference implementation so results compare to published work.

in  detected + annotated events out  per-animal metrics + burden

The scoring library's defaults are built for human seizures — a 30-second tolerance around events that here last five. Left alone they inflate every number without raising an error, so all five parameters are overridden at rodent scale in one place that nothing can bypass.

Build order

The pipeline was built thin end-to-end first — a deliberately weak model carried all the way through to event-level scoring — so that every later change had an honest number to be measured against from day one.
